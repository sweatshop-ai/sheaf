- [x] **A member's `accept` runs on the one shared thread** (`events.py:63`, called from `Shared.get`). `accept` can ask git, so one slow member delays the events of every tab of that browser. Check how slow `accept` gets on a large repo; if it matters, run it per member off the shared thread, or cache its git answer. **Done (measured, no code change):** PR #537. `member_owns` plus `visible` over 300 documents in proxy mode took 2.3 to 3.0 ms per call; no git call on that path; a burst of 100 status events costs about 0.3 s. Moving `accept` off the thread would be a new ticket.

- [ ] **Events that land during a leader hand-over are not replayed** (`live.js`, `Leader.stop` and the `who` rejoin; found in the review of #484). When the leader freezes, closes or crashes, its stream ends, and the next leader opens a new one and every tab joins it again. An event the hub emits between the old stream closing and the tab's new join reaches no tab, and the stream has no event id to resume from. Read from `page.js:4468`: every join is answered by a `hello`, and `meetHello` runs `checkText()`, so a change to the document text in the gap is caught. Nothing in `meetHello` refetches comments, replies, agent progress or the index list, so an event of those kinds in the gap is lost until the next one of its kind. **Reproduction:** three tabs of one browser, the leader frozen (`Page.setWebLifecycleState` `frozen`, as in `test_a_frozen_leader_hands_the_stream_over_and_takes_it_back_on_resume`); while it is frozen and before a follower joins the new leader, post a comment from the API; assert the visible tabs show it within a few seconds. Do the same for the index page's list. **Proposed fix:** the hub numbers the events of each document and puts the latest number in `hello`; a page keeps the last number it saw and, when a `hello` carries a higher one that is not simply the next, refetches comments and replies (and the index its list) as `checkText()` does for the text. Cheaper first step: run that refetch on every `hello` after the first one of the page, since a `hello` after the first means the stream was re-opened. Acceptance: the reproduction passes with the leader frozen at the moment of the event. **Not ticked (2026-11-22):** the frozen-leader reproduction cannot be run in CI today. In headless Chromium, CDP `Page.setWebLifecycleState` `frozen` fires no `freeze` event and the leader holds `sheaf-live` for 40 s and more (ticket 176). PR #542 covers the same gap with the leader closed instead, which the acceptance does not count.
