# Mounting the sheaf page in the front's document: design and security note (#116, step 2)

How the page of a sheaf and the list leave the iframe the front shows them in and run in the front's own document, what that costs in
protection, and what replaces it. Written before the code; the security review of this branch starts here. Decisions taken: the page is rebuilt
in the browser from an allow-list; author SVG is a small allow-list and MathML is dropped; the front gets four CSP rules now and a strict
one report-only for a week; the spike below (selection in a shadow root) has to hold in all three engines before anything is ported.

0. FACTS THAT SHAPE IT
- Today a sheaf page runs in an iframe under its own CSP (default-src 'none'; script-src nonce; img-src data:; connect-src 'self'; base-uri/form-action 'none'). The sanitiser (deny-list, bs4 parse tree, 3 passes) is the second layer, and 9.5 says the CSP "is the defence that holds when this one is wrong".
- The front (Open WebUI) sends NO Content-Security-Policy at all, direct or through Caddy (checked: only HSTS from Caddy), and its page has 3 inline scripts, so it cannot take a strict script-src.
- page.js is 195 KB, one IIFE, written for a whole document: document.body x16, getSelection x8, window scroll x14, localStorage x15, sessionStorage x9, document-level listeners (click x2, mousedown x3, mouseup x2, selectionchange, keydown, resize, storage, blur, visibilitychange x2, beforeunload), 15 innerHTML/insertAdjacentHTML sites, location.reload x3, EventSource /_/live. page.css selects on body classes (body.rd-editing, body.notoc), has 8 position:fixed rules and a prefers-color-scheme block.
- The page is assembled in render.py (inline <style>, inline nonce'd page.js, config as <script id="rd-edit-meta" type=application/json>).
So after step 2 a hostile sheaf (mail text, a comment body, an agent's page) is DOM in the origin of the signed-in member's session. "Sanitiser + CSP" becomes "sanitiser + whatever I add". The design below adds three layers so that no single deny-list bug is enough.

1. WHAT THE MOUNTED PAGE NEEDS FROM THE FRONT
Hub side (new, no change to existing routes):
- GET /_/mount/<doc path> (same member gate as /_/*, same Caddy route, already covered by the /_/* rule): JSON {html: the sanitised body, config: today's rd-edit-meta, title, version}. The existing page route stays for the share copy, PDF and the loopback mode.
- GET /_/mount.js and /_/mount.css: page.js (+ the list's script) and page.css as files, versioned by the hub's version/hash in the URL (immutable cache), the hub's own trusted assets.
- The list page (the_list.py: its own CSS and SCRIPT, innerHTML 0, location.reload 1) gets the same JSON form, so list <-> sheaf is one pushState navigation. Other hub pages (/, mails) are out of scope and keep their own documents.
Loader side (loader.js, via a stage):
- Loads /_/mount.js once with a script element (the front has no CSP, so same-origin src is allowed) and calls mount(el, path) in the pane: el is the same pane node the iframe sits in today. pushState on every move, popstate hands each stop to the page (what 1b already does, minus the frame). The loader drops: the iframe, watchTheme's cross-document copy, the phone bar and the keyboard code (no frame means no mismatch of viewports).
CSS: a shadow root on a host div. page.css goes into the root as a <link> or adoptedStyleSheets from /_/mount.css; body selectors become :host / a .rd-root wrapper class; theme variables (--bg --fg --accent ...) are set by the loader on the host, as it sets them on the hub's root today. Reason for a shadow root: the page's CSS and the front's cannot touch each other, and an author's id/name in the document cannot clobber the front's globals (DOM clobbering applies to the document tree, not a shadow tree).
Scripts/events: page.js becomes create(root, cfg) returning {unmount, dirty, remount}. document -> root (getElementById/querySelector), document.body -> the wrapper, selection through Selection.getComposedRanges (shadow-aware; Baseline in current Chrome/Firefox/Safari, to be confirmed on the target browsers in the rehearsal) because comments anchor on the selection, scroll through the pane's scroller instead of window. Every document/window listener goes through one registry that unmount() removes; EventSource closed in unmount(); location.reload() becomes remount() (refetch, keep scroll/caret as reloadKeep does today); localStorage/sessionStorage keys prefixed (they now share the front's origin); beforeunload: the loader asks page.dirty() before a pushState move and holds a beforeunload while dirty; a Back that the page would cancel cannot be cancelled by popstate, so the loader pushes the entry back and asks (policy: the owner decides, default = confirm dialog).

2. WHAT THE SANITISER MUST BLOCK ONCE THE SHEAF'S OWN CSP IS GONE
Three layers.
(a) Server: the existing sanitiser, plus the gaps below, with red tests first.
(b) Client: mount.js does not put hub text into the page with innerHTML. It parses the JSON html with DOMParser (inert: no scripts run, no loads), then builds the tree node by node with createElementNS from an ALLOW-LIST of elements and attributes, text through textContent. A browser re-parse (mutation XSS: namespace confusion in svg/math, noscript/template/style parser tricks) cannot occur because nothing is re-parsed. Limits on depth and node count.
(c) Front: a CSP added by Caddy (section 3).
Gaps in the present deny-list that the CSP used to cover, each gets a red test:
- Execution: <script>, on* handlers, javascript:/vbscript:/data: hrefs and srcs (also with tabs/newlines/entities), srcdoc, <iframe>/<frame>/<object>/<embed>/<applet>, <base>, <form>/formaction/<button>/<textarea>/<select>, <template>, <noscript>, <meta http-equiv=refresh> (meta is removed, but test it with every case), <link rel=...>, <style> and @import, svg <script>, svg <set>/<animate> on href (partly covered: attributeName test only; also to/values/from), svg <use href=external>, svg <foreignObject> (HTML parsed inside svg), svg <image href=http...>, MathML (maction, mglyph, annotation-xml encoding=text/html, href on any math element), xlink:href everywhere.
- Phone-home (the CSP's img-src data: and connect-src 'self' blocked these, and nothing blocks them on the front): <img src=https://...> (tracking pixel; mail text is hostile), <video>/<audio>/<source>/<track> src and poster, <input type=image>, srcset (dropped already), svg <image>, CSS url(...) and image-set() in a style attribute, <a ping> (dropped), prefetch via link (removed). Rule: img src only data:image/(png|jpeg|gif|webp) or the hub's own relative path; everything else is dropped and its alt text or link shown instead.
- Style attribute: today kept. Once the document's CSP is gone it can overlay the front's UI (position:fixed/absolute, z-index, transform, huge font, pointer-events), load (url()), and spoof. Rule: allow-list of properties (text-align, width, color, background-color, font-weight/style, text-decoration, vertical-align, simple border/margin/padding/list-style) and values by a strict regex with no url(, image-set(, var(, expression(, backslash escapes or comments; everything else removed. Test: position:fixed overlay, background:url(), content:, -moz-binding, behavior:, nested-quotes tricks.
- Identifiers: author id/name/class can collide with the page's own ids (rd-popover, rd-*): rewritten into an author namespace (id="u-<id>", href="#u-<id>", name attributes dropped) in the client rebuild, and the page's TOC and anchors use the same map. Test: an author <div id="rd-popover"> must not receive the page's popover.
- Navigation: a href only http/https/mailto and relative/fragment (file: is dropped: it is dead on a remote page and was only for loopback); target removed, rel="noopener noreferrer" forced; no <a> in svg with scripts.
- Where each test lives: tests/test_sanitize.py (server side, red-first as you asked), a new tests/page/test_mount_allowlist.py (the client rebuild in real Chrome: feed the hostile corpus through mount() and assert no script ran, no request left the origin (route interception counts requests), no element outside the allow-list exists, the page's own ids are untouched).

3. WHAT CSP THE FRONT ITSELF THEN CARRIES
Today none. Because Open WebUI needs inline scripts (and likely eval), a script-src that blocks injected script is not available; the CSP buys the rest:
- Enforced now (safe for Open WebUI, none of its features use these): object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'self'. It closes plugins, <base> hijack, form-post exfiltration and framing of the front.
- Report-only (observe first, one week): img-src 'self' data: blob: https:  is NOT useful against beacons (https: allowed); the useful one, img-src 'self' data: blob: plus connect-src 'self' wss:, may break chat images and any direct connection the front makes from the browser, so it ships as Content-Security-Policy-Report-Only, read from the console during the owner's checks, then enforced or dropped by the owner's decision. I would not enforce it unobserved.
- The hub's own pages keep their CSP; frame-ancestors goes back to 'none' (SPEC 9.5/9.9 and the proxy-mode test row), the 'self' exception dies with the frame.
- Referrer-Policy: same-origin on the front, so a click on an external link in a sheaf never sends the path (client and project names) as a Referer.
This is Caddy (the site block that already fronts both), so it is part of the stage.

4. WHAT BREAKS / DECISIONS
- The ADR 0002 trade-off ("a script on the front's origin acts as the member") now also covers hostile document text. The layers above make that a bug-in-three-places failure, not one; it is still a weaker position than the frame today. The deployment's owner has chosen this step; the security review of the branch is the gate.
- Selection/comment anchoring in a shadow root is the biggest functional risk (page.js has 8 getSelection sites). I would prove it in the first slice with a spike test in real Chrome, Firefox and WebKit (Playwright) before porting the rest.
- Dirty Back policy (above); the comment popovers and the 5 s Undo windows (#110/#111) must survive a remount.
- Shipping needs a new hub: a sheaf release installed by the hub stage (the pinned-wheel stage of the sheaf module), plus the loader and Caddy stage. Two stages, hub first (new routes, nothing visible), then loader+Caddy (the switch). Rollback of the second brings the frame back with the hub still new; rollback of the first is the old wheel. No tag (release rule): the wheel is built from a commit and pinned by sha.
- Clash risk: open work touches render.py BASE_CSS and SPEC line 950, and #127 (the four P3s of #111) edits page.js's press code. A 3400-line page.js refactor conflicts with any parallel page.js edit, so #127 waits until this lands.
- Options I weighed and do not recommend: serving the page from a different origin (breaks the one sign-in, ADR 0002); a sandboxed iframe with srcdoc (an iframe again, with the same history/keyboard faults); trusting the server sanitiser alone.

5. PLAN
1 this note; 1b the selection spike (section 6); 2 red tests: tests/test_sanitize.py hostile corpus (all items in section 2) and tests/page/test_mount_allowlist.py; 3 build in slices on a branch off main: (i) mount()/unmount() spike with selection in a shadow root on 3 browsers, (ii) JSON routes + assets + allow-list rebuild, (iii) the list page, (iv) the loader and Caddy CSP, each with its tests; 4 /security-review on the branch, every finding fixed and tested; 5 a fresh Opus GO naming the commit; 6 two stages with rollback tested to a reload, READY, then the owner's go and a browser check by the owner.

6. SPIKE RESULT: SELECTION IN A CLOSED SHADOW ROOT (slice i)
`tests/page/test_mount_selection.py`, 11 scenarios x 3 engines, 33 passed (Chromium 145, Firefox 146, WebKit 26; Firefox and WebKit are the Ubuntu 24.04 builds of Playwright 1.58 run on a newer host). With `Selection.getComposedRanges({shadowRoots: [root]})` the page gets, in all three: the quoted text and offsets of a mouse drag inside one block, across two blocks and through inline elements; a word (double click) and a block (triple click); a selection set by code, read back with the same offsets; a range it can wrap with `surroundContents` (how page.js wraps an anchor); a bounding box for the popover; `selectionchange` on the document; typing, a collapsed caret with its offset, Shift+Arrow selection and replacement inside a `contenteditable` block of the root; focus (`document.activeElement` is the host, `root.activeElement` the block).
Findings that change the design:
- Firefox does not retarget the plain `getSelection()` out of the root: `anchorNode` is a text node inside it (Chromium and WebKit hand out a light-tree node). So a closed root is not a boundary against a script that reads the selection in Firefox, and the allow-list rebuild and the CSP stay the defences; nothing in the design relied on the closed root for that.
- A drag that starts outside the root and ends inside it is not a comment anchor: the page requires both ends inside the root, which the composed range lets it test.
Not covered by this spike, to be proved in the build: iOS Safari touch selection handles (WebKit on Linux is not iOS), the real page.js code paths (the spike is the browser contract, not the port), and IME composition.

## 7. Slice (ii) as built: where it differs from section 2

- **The route is `GET /_/mount?doc=<address>`**, not `/_/mount/<path>`: the hub's route table matches the path exactly and every other `/_/` route takes the sheaf as `?doc=`. Same gate as `/_/doc` (a member's cookie or the key); the member sees what they could open. The assets are `GET /_/mount.js` and `/_/mount.css`, open (public code), kept for a year only when the request names the hub's version (`?v=`), `no-store` otherwise.
- **One meta, two routes.** The state the page route puts in the meta block (seen, agent, can, lines, the member's work, the buttons) is now one function, `Hub._fresh_meta`; the mount route calls the same one, so a mounted page cannot read a different state from a framed one.
- **Mount mode is a keyword of the same sanitiser** (`sanitize(..., mount=True)`), so the share copy and the loopback page keep their rules. The body is rendered on each request, not cached: one pandoc call.
- **Found while testing: nesting is a way to freeze the front's tab.** Chromium's `DOMParser` costs the square of the depth: 20.5 s for 100,000 nested divs (measured; Firefox and WebKit are faster). Two limits answer it. The mount sanitiser replaces anything nested deeper than 100 by its text; `mount.js` scans the tags before parsing and refuses a text nested deeper than 1,500 (`<x/>` counts as open outside svg, as the HTML parser reads it) with a one-line message instead of the page.
- **Every id in the rebuilt tree is namespaced, the page's table of contents included**: the `nav#toc` the hub renders becomes `u-toc`. The page's own structure (the wrapper, the popover, the toolbar) is created by `mount()` and is not in the JSON, so the page port in the next slice looks for its parts by what it created, not by the ids the document carries.
- **Not in this slice**: page.js and page.css in the root (`create(root, cfg)`), the list page, the loader and Caddy. `mount()` builds a closed root with the document's styles and its rebuilt body and returns `{config, title, toc, unmount}`; nothing in it is interactive yet.

## 8. Slice (iii) as built: page.js and page.css in the root

- **One page.js for both.** The IIFE is now `create(ROOT, CFG, opts)`. The page of its own calls `create(document, meta)` at the end of the file as before; `mount()` calls `sheafPage.create(root, config, {body: wrap, remount})`. Nothing was forked. `ROOT` replaces `document` for finding elements (`getElementById`, `querySelector(All)`, `activeElement`); `BODY` replaces `document.body` (the wrapper `.rd-root` when mounted). `/_/mount.js` is `mount.js` followed by `page.js`, and `/_/mount.css` is `mount.css` followed by `page.css`. Both are files from the hub's own package.
- **Listeners**: every document or window listener goes through `listen()`, and `unmount()` removes them. When mounted, clicks, mousedown/up with a target, mousemove and keydown are heard on the root, because the front's document sees them retargeted to the host and a closed root's `composedPath()` hides the rest. `selectionchange`, `visibilitychange` and the mouse-state captures stay on the document; `resize`, `storage` and `blur` stay on the window. A click on the wrapper focuses it (`tabindex=-1`), so the page's keys reach the root. `beforeunload` and `unhandledrejection` are registered only on a page of its own. A mounted page reports only the window errors whose file is `/_/mount.js`, so the front's own errors are not logged as the page's.
- **Timers**: `setTimeout` and `setInterval` are local wrappers that do nothing once the page is unmounted; `unmount()` clears the intervals, closes the EventSource and deletes the page's four highlights, which live in the document's registry.
- **Selection**: `getSel()` returns `window.getSelection()` on a page of its own. Mounted, it returns an object with the part of Selection the page uses, read from `getComposedRanges({shadowRoots:[root]})` and set through `setBaseAndExtent`. A range counts only when both of its ends are in the root.
- **Geometry**: `viewRect()` (what can be seen, in client coordinates) and `pageOrigin()` (client to absolute position) replace `window.scrollX/Y`, `innerHeight` and `clientWidth` in the popover, the Comment button and the panel's edge. On a page of its own they give exactly the old values. Mounted, the wrapper is the scroller (`position:relative; overflow:auto; height:100%`), and `contain: content` on the host makes the page's `position:fixed` parts belong to the pane instead of the front's window.
- **Reload**: the two `location.reload()` calls are now `reloadPage()`. Mounted, that is `remount()`: fetch, `unmount()` the old page, build the new one. The sessionStorage keep (scroll, caret, open comment, panel, held reloads, sent lines) is the one a reload already used, so whatever survived a reload survives a remount.
- **Storage keys**: when mounted, every key carries the prefix `sheaf-mount:`. A page of its own keeps its keys, so drafts written before this change are still found.
- **CSS**: `body.rd-editing` and `body.rd-show-resolved` became `.rd-editing` and `.rd-show-resolved`. The class sits on `document.body` or on the wrapper.
- **innerHTML and stranger text**: the page's innerHTML sites build its own markup. The text they carry from the hub (comment bodies, replies, names, quotes) goes through `esc()` first, and comment markdown goes through `mdLite`, which escapes before it adds `a` (http(s) only), `strong`, `em`, `code`, `ul`, `ol`, `li`, `p` and `br`. No hub HTML reaches innerHTML; the document body comes only through `sheafMount.rebuild`. For the review: `esc` does not escape `'`, and every attribute the page writes is double-quoted.
- **Tests**: `tests/page/test_mount_page.py`, 9 tests, all red on 132cc22. A comment dragged in the closed root reaches the file in Chromium, Firefox and WebKit. The other 6 run in Chromium: the parts sit in the root and none in the front; the menu opens and closes; the Comment button sits under the selection in the pane; an edit makes `dirty()` true and is stored under a prefixed key; an outside change remounts in place, keeps the scroll and does not reload the front; `unmount()` leaves no request, no listener and no highlight.
- **Not in this slice**: the Dirty Back confirmation (the loader asks `dirty()`; slice v). Docking above the iOS keyboard still uses the visual viewport, which is the window's (iOS goes on the final list). The list page is slice (iv).
