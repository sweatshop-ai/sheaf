## For BU (a foreign comment before a lone tag at the start of a list item loses the tag)
- Cause: pandoc reads `- <!-- f --></x1>Start b here.` as a list item whose content is a **RawBlock** (an HTML block of type 2 starts at `<!--`), so the whole line, `</x1>` included, is raw HTML. `_raw_tags(content)` collects only RawInline tags, so the `</x1>` is never a lone tag: `_lone_as_text` is not called, nothing puts it back, and the guard in the comment conversion (`block holds raw HTML the edit cannot keep`, `edit.py` about line 2471) only checks the tags `_tags_as_text` placed. The browser drops `</x1>`, and the save writes the item without it, refused by nothing.
- Same item with a sheaf comment (`<!-- sheaf-comment ... -->`, which spans lines) is refused by that guard: nothing is lost there.
- Without the comment (`- </x1>Start b here.`) pandoc reads a Plain with a RawInline `</x1>`, and the tag is kept.
- Direction: a refusal is the safe fix. A tag inside a RawBlock nested in the block that the new markdown no longer holds should refuse the save, with the existing message.
- Probe: `- a\n- <!-- f --></x1>Start b here.` with page `<ul>\n<li>a</li>\n<li><!-- f -->Start b there.</li>\n</ul>` saves as `- a\n- <!-- f -->Start b there.`, on main and with BS.

## For BV (a comment at the end of an emphasis, tag after the emphasis: the tag moves inside it)
- Cause: BS's `lead` counts only Comment **siblings** of the text that starts with the tag's placeholder. In `*Start<C1>*</x1> b here.` the comment is the last child of the `<em>`, one level down, so `lead` is 0. The tag is then placed right after "Start", inside the emphasis and before the comment's placeholder: `*Start</x1><C1>* b there.`.
- Direction: when the sibling before the tag's text is an element, `climb` already tells how many elements close between the words and the tag. The count has to look at the comments at the end of that element (its last descendants), and placement has to go after them and then climb out, keeping the existing `climb` logic.
- Probe: `*Start<C1>*</x1> b here.` with page `<p><em>Start<span class="rd-anchor" data-rd-id="c1"></span></em> b there.</p>` (C1 as in the test file).

## For BX (#631's review: the count says how many comments, not which)
- `lead`/`trail` hold a number; on the page `comment_re` steps over any comment placeholder. If the user deletes the comment on one side of the tag and keeps the other, the tag steps over the wrong one (`Start<c1></x1><c2>` with c1 deleted saves `Start<c2></x1>`).
- Direction: record which comments (sheaf ids, raw text for foreign ones) and step only over those. BV's fix touches the same count, so BV and BX go well together.
