# 156: A page a job generates is read-only for text edits in the hub

**Status:** open (feature not built; where the mark lives is still to decide)

**From:** render-doc ticket 156 (private archive), triaged 2026-11-12

**Where (main 81afdff):** `src/sheafmd/render.py:1137-1147` (page meta `edit` and `why`), the MCP door's `create`/`update` in `src/sheafmd/mcp.py`; SPEC 4.2, 7.1-7.3, 8.3, 8.5, 9.7, 10.1, 10.3, 12

**Size:** a decision, then a feature of several sessions, spec first

- [ ] **The problem.** A page that a job rebuilds through the MCP door's `update` (with a fresh `expected_hash`) silently overwrites an edit a person saved in the hub a few seconds earlier; nothing tells the person. Add a per-document "generated" mark that makes the page read-only for text edits while keeping comments, replies, resolve, Ask and Tell working. Nothing in SPEC or in the door sets such a mark today (`git grep -i generat -- SPEC.md` finds nothing about it).

- [ ] **Decide where the mark lives.**
  - (1) hub state in `docs.json` (SPEC 4.2, 8.3), set by `create`/`update` with `generated: true|false` and recording the setting token's name. Recommended, so "only that token or the key may change it" is enforceable.
  - (2) front matter `generated: true`: visible in git, but any writer can set or clear it.

- [ ] **With the mark:**
  - page meta `edit: false` plus a `why` (`src/sheafmd/render.py:1145-1146`), no `E` key and no Edit in the menu, a short notice ("Generated by <token name>. Edits are not kept; comment instead.");
  - `POST /_/save` and task-box ticks refused with a clear message and a diagnostics row without the text;
  - `update` or create-over by another write token refused, accepted from the setting token or the key; a revoked setter leaves the mark, which only the key can clear;
  - `read` and `tools/list` expose `generated`.

- [ ] **Tests red first** for each of: meta `edit:false` + `why`; save refused; tick refused; `update` by a second token refused vs the setting token or the key accepted; clearing by a second token refused; comment, reply and resolve still work and `update` still keeps every comment. SPEC 4.2, 7.1-7.3, 8.5, 9.7, 10.1, 10.3 and 12 updated before the code; one README paragraph for modules that generate pages.
